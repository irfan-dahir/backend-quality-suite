You regenerate the generated parts of a mock-API contract — `{{doc:api}}`'s
example JSON block and the Postman collection's example response body — from
its fixture, instead of hand-editing three artifacts and letting them drift
(the exact failure that hit `GET /plans`: a broad `git checkout HEAD --`
revert during this session silently rolled back the doc + mock re-contract
while the Dart client stayed on the new shape).

**You regenerate two files from one; you never invent example values.**

`{{dir:plans}}/mock-api-integration.md`'s "Contract automation" section.

## Source-of-truth chain

1. **The Dart model's `fromJson`** — defines field **shape** (names). This is
   what a designer or dev changes when a feature's data actually changes.
2. **The fixture** (`test/fixtures/<name>.json`) — the **one file a human
   hand-edits** for example **values**. Shape must match the model; values
   are a judgment call (realistic sample data, edge cases) this skill never
   invents.
3. **Generated from the fixture**: `{{doc:api}}`'s `​```json` example block
   under the endpoint's anchor, and the Postman collection's example
   response body for that request. Both regenerated byte-for-byte from the
   fixture — never hand-edited once a contract has an entry here.

The field table's **Notes** column and the surrounding prose in `{{doc:api}}`
stay hand-written. Shape can be generated; judgment about *why* a field
exists can't.

## Step 1 — Locate or add the contract entry

Check `<pipelines.mockApi>/contracts.json` for the endpoint. If it's not there yet
(a new Phase 1+ endpoint), add an entry:

```json
"caregivers_list": {
  // Paths in this example are illustrative — they come from the project, not
  // from this skill. A different stack has different shapes here.
  "model_file": "<source.root>/features/<feature>/data/models/<name>_model.dart",
  "fixture": "<source.testRoot>/fixtures/<name>_example.json",
  "fixture_list_key": "caregivers",
  "api_doc_anchor": "#### `GET /caregivers`",
  "mock_folder": "caregivers",
  "mock_request": "GET /caregivers"
}
```

If the fixture doesn't exist yet, create it from the model's fields plus
realistic example values — ask the user for anything that needs a product
judgment call (what a "typical" example looks like), same as `/scaffold-screen`
asks rather than invents.

## Step 2 — Run the sync

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/backend_suite/engine/mockapi/sync_mock_api.py" <contract-name> --write
```

The bare command (no `--write`, and `--check` is the same thing spelled
explicitly) never writes anything — it prints `direction: fixture ->
{mock, docs}` plus what would change, and names exactly what would be
**lost** if the fixture is missing something the target still has. Only
`--write` touches a file.

If the fixture is the poorer side (issue #116: a mismanaged fixture edit
had already dropped a real field the mock still carried), `--write` refuses
— exit 2, with the lost key/value named — until you either fix the fixture
or pass `--write --allow-loss` because the loss is genuinely intentional. A
fixture that only grows richer never triggers this; it's not a loss.

`sync_mock_api.py` also prints any field-table drift it can't auto-fix
(documented fields the model dropped, or vice versa — those need a human to
edit the Notes column, so it warns instead of guessing).

See also `/audit-mock-api`, the read-only counterpart, and the
`PostToolUse` hook that nudges this after a model/datasource edit.

## Step 3 — Review and commit

Diff `{{doc:api}}` and the mock collection file (whatever `mock_provider.file` names) — confirm
the regenerated example is what you expect, then commit both together
(never split doc from mock in separate commits — `{{doc:pr}}`'s "one
reviewed unit" rule for these two files stands).

---

## What you must never do

- Invent example values instead of asking when a fixture doesn't exist yet
- Hand-edit the generated example block in `{{doc:api}}` or the mock's
  response body directly — edit the fixture and re-run the sync instead
- Touch the field table's Notes column or prose — those are generated-shape
  adjacent, not generated
- Skip re-running the sync after editing a fixture, and commit the two out
  of sync with it
